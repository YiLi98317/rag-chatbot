# 商务、客服、业务员协作说明书

> 适用对象：商务团队 / 客服主管 / 业务员 / 运营  
> 目的：告诉他们要提供什么、怎么写、怎么审核

---

## 1. 你们为什么要参与

马三多 AI 助手不是普通聊天机器人，它要代表公司回答加盟商、老板、店员的问题。

它能不能上线，不只取决于技术，更取决于：

- 公司规则有没有整理清楚
- 标准答案有没有统一
- 销售话术是否靠谱
- 禁止话术是否明确
- 转人工规则是否清楚
- 错误回答有没有人纠正

所以你们不是来“试用 AI”的，而是来定义“公司认可的正确答案”。

---

## 2. 你们要交付什么

### A. 高频问题

每个人至少整理 20 条。

格式：

```text
问题：
老板/客户/店员真实怎么问？

标准答案：
公司认可怎么答？

适用对象：
加盟商 / 店员 / 客服 / 业务员 / 内部管理

风险点：
哪些话不能说？哪些情况必须转人工？

来源：
依据哪份规则或谁确认？
```

---

### B. 标准规则

请整理正式口径，不要只给聊天记录。

需要：

- 商家入驻规则
- 办单流程
- 服务费和设备管理费说明
- 结算规则
- 审核失败处理
- 监管锁说明
- 售后质保
- 丢失/逾期/买断/退款
- 活动政策
- 返点/奖励政策
- 风险/合规红线

---

### C. 标准话术

每条话术最好分三段：

```text
客户版话术：
可以直接发给客户/老板看的话。

内部解释：
告诉店员为什么这么说。

不建议说法：
哪些表达容易出事，不要说。
```

---

### D. 禁止话术

请确认以下表达是否禁止，是否要补充：

- 贷款
- 利息
- 套现
- 包过
- 百分百通过
- 一定通过
- 一定发货
- 交钱就能过
- 风控规则是
- 内部审核标准
- 不还也没事
- 可以绕过
- 规避监管
- 帮你套机

如果某个词不是绝对禁止，也要说明：

- 哪些场景不能说
- 哪些角色不能看
- 可以用什么替代表达

---

### E. 转人工规则

请列出：

```text
问题类型
AI 是否能答
如果不能答，转给谁
标准兜底话术
```

示例：

| 场景 | AI 是否能答 | 处理 |
|---|---|---|
| 客户投诉服务费 | 不能直接定性 | 转人工 |
| 客户要求减免 | 不能承诺 | 转人工 |
| 问风控内部规则 | 不能透露 | 拒绝 + 转人工 |
| 订单异常 | 看系统状态 | 不确定则转人工 |
| 套机/规避监管 | 不能提供方法 | 拒绝 + 转人工 |

## 3. 知识库文档怎么写

统一模板：

```markdown
---
doc_id:
title:
category:
visible_to:
risk_level:
owner:
reviewer:
version:
effective_from:
effective_to:
source_type:
---

# 标题

## 适用场景

## 标准答案

## 操作步骤

## 客户版话术

## 店员内部解释

## 禁止说法

## 必须转人工

## 备注
```

字段说明：

| 字段 | 含义 |
|---|---|
| doc_id | 文档唯一编号 |
| title | 文档标题 |
| category | rules/sop/sales_scripts/redlines/faq 等 |
| visible_to | 谁能看：加盟商、店员、客服、业务员、内部管理 |
| risk_level | low / medium / high |
| owner | 业务负责人 |
| reviewer | 审核人 |
| version | 版本，例如 2026-07 |
| effective_from | 生效时间 |
| effective_to | 失效时间，没有就空 |
| source_type | official_policy / sop / sales_script / faq / redline |

## 4. golden 测试题怎么审核

现在有一版 54 道 AI 测试题。

你们需要审核每题：

| 字段 | 你们要判断什么 |
|---|---|
| question | 这个问题真实常见吗？ |
| category | 分类对不对？ |
| role | 这个角色对不对？ |
| expected_answer_points | 标准答案要点对不对？ |
| forbidden_terms | 禁用词对不对？ |
| must_handoff | 是否必须转人工？ |
| ideal_reply | 这句话能不能直接用？ |
| needs_business_review | 是否已经确认完？ |

审核结果填：

```text
正确 / 需要修改 / 待确认 / 删除
```

如果要修改，必须写出修改后的标准答案。

## 5. Langfuse 质检怎么做

每次看一条 AI 回答时，按照这 6 个问题检查：

1. 问题是什么？
2. AI 回答是否正确？
3. AI 有没有乱承诺？
4. AI 有没有用错词？
5. AI 是否应该转人工？
6. 正确答案应该是什么？

评分：

```text
5 分：完全正确，可以直接用
4 分：基本正确，表达可优化
3 分：方向对，但缺关键点
2 分：明显误导，需要改
1 分：错误
0 分：违规/胡编/高风险
```

错误类型：

```text
ok
knowledge_missing
knowledge_outdated
retrieval_miss
answer_not_grounded
route_error
redline_miss
bad_sales_script
should_handoff
unnecessary_handoff
```

## 6. 分工

### 商务负责人

负责：

- 费率
- 服务费
- 活动政策
- 加盟商政策
- 结算规则
- 红线中的费用/承诺类表达

### 客服主管

负责：

- 售后
- 审核失败
- 质保
- 投诉
- 转人工规则
- 标准客服话术

### 业务员/店员代表

负责：

- 销售话术
- 客户异议
- 客户嫌贵
- 监管锁解释
- 成交话术
- 错误话术案例

### 运营/产品

负责：

- 系统操作流程
- 后台页面路径
- 办单 SOP
- 营业员新增
- 结算账户绑定

### 项目负责人

负责：

- 统一格式
- 整理知识库
- 组织审核
- 跑 benchmark
- 看 Langfuse 数据
- 输出下一轮优化任务

---

## 7. 最重要的原则

1. 不确定就标“待确认”，不要编。
2. 过时规则不能进正式库。
3. 群聊截图不能直接进知识库，必须整理成标准答案。
4. 销售话术要能复制给真实客户。
5. 红线话术必须保守。
6. AI 答错时，不要只说“错了”，必须给正确答案。
7. 标准答案不能为了让 AI 过测试而降低要求。
