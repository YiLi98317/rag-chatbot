## 已确认（2026-07-03，用户答复后落定）

- **D4｜`masanduo_624/` 判定为无用备份** → 视为死代码，冻结、不再参考，本轮仍不删。
- **D5｜部署形态固定为 systemd + scp** → docker-compose / k8s 清单视为未使用（不投入维护）。
- **D6｜评分目的 = 知识治理闭环，不为微调** → 评测/评分产物直接服务于「改知识库」，而非训练数据（微调是远期可选项）。
- **D7｜评分采用「人工 + LLM 自动」结合**。
- **D8｜前端归属 `pc_sjmm`，且当前不传 `session_id`** → 会话/角色能力需前端配合，属跨仓库改动。
- **D9｜「维护+评分后台」采用 Langfuse（用户 2026-07-03 选定）** → 作为可观测 + 人工/LLM 评分 + 数据集/评测的统一后台。落地=在该 A10 服务器 docker 自托管（docker 已就绪、数据不出境）。
- **D10｜生成模型 = DeepSeek API（deepseek-chat）** 作为第一步；本地 Qwen（A10）作为后续降本/合规演进（用户选 both_later 方向，先 API）。
- **D11｜nginx 反代迁移 = 待安全组放行面板端口、能登面板后再做**（最稳，避免线上开天窗）。
- **事实澄清（embedding/向量库）**：服务器 `.env` 实为 `EMBED_PROVIDER=sentence_transformers` + `EMBED_MODEL=Qwen/Qwen3-Embedding-8B`（**本地 Qwen3-Embedding-8B 跑在 A10，即 ~14.7GB 显存占用**），向量存于 **Milvus Lite 文件 `milvus.db`（758MB）**，collection=`chatbot_docs`。用户"当初用 Qwen embedding 后来找不到"的困惑=数据一直在 `milvus.db` 里，未丢，已备份。
- **D12（推荐，待用户确认）｜向量库保留 Milvus Lite**，重建时弃用 docker Milvus Server 空转栈。⚠️ 关键约束：**更换 embedding 模型必须重新 ingest**（向量与模型绑定，维度/语义不通用）。
