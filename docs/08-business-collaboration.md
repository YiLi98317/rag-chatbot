# 08 · 业务协作指南（负责人 + 商务团队）

> 给项目负责人开会用的讲解稿 + 给业务团队的分工。核心一句话：
> **模型是执行层，知识库和评测标准才是公司的资产——这部分只能业务来定。**

## 1. 为什么需要业务团队参与

马三多（AI）本身不懂你们的规则，它是"查知识库 + 按标准答"。
所以答得好不好，取决于两件业务的事：
1. **知识库对不对、全不全**（规则/流程/话术/红线）。
2. **标准答案（golden）对不对**（拿它给 AI 打分）。
这两件事技术做不了主，必须业务定。

## 2. 业务团队要提供什么素材

| 素材 | 谁提供 | 形式 |
|---|---|---|
| 真实高频问题 | 业务员/店长 | 客户/加盟商实际怎么问，越口语越好（目标≥50条） |
| 平台规则/费率/结算口径 | 商务负责人 | 确认现有知识库对不对、补缺 |
| 办单/锁机/审核/售后 SOP | 客服主管 | 标准操作步骤 + 常见异常 |
| 销售话术 | 业务员/运营 | 能直接说给客户的原话 + 出过问题的说法 |
| 禁用话术清单（红线） | 运营/法务/管理层 | 绝对不能说的词与替代说法 |
| 活动/费用政策的生效失效时间 | 运营 | 带日期 |

## 3. 三件具体工作（业务侧）

1. **审 golden**：见 `docs/07-golden-review-guide.md`，在表格里确认/修正标准答案。
2. **写知识库**：用 `data/knowledge/_templates/` 里的模板写，见 `docs/09-knowledge-base-structure.md`。
3. **在 Langfuse 打分**：给 AI 的真实问答打分、标注问题（见下）。

## 4. Langfuse 怎么质检（业务版）

- Langfuse 是我们自己服务器上的"AI 问答记录 + 评分后台"，能看到每条真实问答（问题、回答、命中了哪块知识、耗时）。
- 界面是**英文**（官方无中文）：用 Chrome/Edge 的"翻译成中文"或装"沉浸式翻译"插件即可整页变中文。
- 业务同事主要用两块：
  - **Tracing / Sessions**：看真实问答记录。
  - **Scores / Annotation**：给回答打分（5 分制）+ 写评语。
- 看到答错的：记下来 → 变成"知识库要补的内容"或"golden 里的新题"。这就是闭环。

## 5. 分工表

| 角色 | 负责 |
|---|---|
| 项目负责人（你） | 统筹、拉会、把业务反馈交给技术 |
| 商务负责人 | 入驻/返点/提现/结算规则 + 红线合规审核 |
| 客服主管 | SOP/审核/锁机/售后口径 + 转人工判断 + Langfuse 打分 |
| 业务员/店长 | 真实高频问题 + 销售话术 |
| 运营 | 活动/费用政策+生效时间 + 禁用话术清单 |
| 技术（AI 侧） | 工具、ingest、评测、修 bug（不定业务口径） |

## 6. 一周推进计划

| 时间 | 事项 | 产出 |
|---|---|---|
| Day 1 | 开会讲解本文档 + 分工 | 大家知道各自要干啥 |
| Day 1-2 | 业务员汇总真实高频问题 | ≥50 条问题清单 |
| Day 3-4 | 商务+客服审 golden（先 needs_business_review） | 填好的 golden_review 表 |
| Day 5 | 运营出禁用话术清单 + 政策生效时间 | 红线清单、政策表 |
| Day 6 | 客服主管在 Langfuse 试打分 10-20 条 | 首批人工评分 |
| Day 7 | 技术合并反馈、重跑 benchmark | 第一份对比分数 |

## 7. 开会时可以这样讲（口径）
> "我们不是要训练一个 AI，而是要建一套'公司标准答案库'。AI 只是照着答。所以请大家把真实问题、正确口径、不能说的话给到我，我们用一套考试题（golden）定期给 AI 打分，答错的就回来补知识库。第一阶段不碰模型训练，先把知识库和标准答案做扎实。"
