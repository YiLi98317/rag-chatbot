# 00 · 项目简介（Project Brief）

> 说明：本文件区分「✅ 已确认（基于实际读到的文件）」与「❓ 待确认（推测，需用户确认）」。

## 一句话

一个基于 **RAG（检索增强生成）** 的中文问答机器人，被改造为**手机租赁 / 回收平台**的商家（门店老板、加盟商、店员）问答后端，人设名为「**马三多**」——平台 AI 商务 / 销售军师。

## 业务目标

- ✅ 面向 B 端商家回答业务问题：回收价、租机费用测算、库存、平台规则/费率、办单流程、参数卖点、销售话术等（依据 `src/chatbot/masanduo/SOUL.md`、`router.py` 的意图集合）。
- ✅ 对高风险问题给**固定合规话术**并拦截（如「套机」「监管机」→ `replies.py` 固定文案，不走 LLM）。
- ❓ 长期目标（来自用户本轮说明，非代码）：做成「公司规则大脑」，并搭一个**后台专门维护会话（chat session）并做评分/评测**。当前代码尚无此后台。

## 主要用户

- ✅ 手机租赁平台的**门店老板 / 加盟商 / 店员**（人设称对方为「老板」）。
- ❓ 是否也面向 C 端消费者：**待确认**（当前话术定位是帮老板卖货、答规则，偏 B 端）。

## 核心功能（✅ 依据 `router.py` / `SOUL.md` / `compute.py` 意图）

1. 查回收价（靓机汇报价）
2. 算租机方案（售价+折扣+期数 → 费用表）
3. 复合推演（机型+预算/旧机 → 折抵+方案匹配）
4. 查库存 / 定价分析
5. 平台规则 / 费率 / 办单 / 锁机说明
6. 参数卖点 / 机型对比
7. 销售话术 / 经营干货 / 电商素材文案
8. 合规红线拦截（套机、监管机）
9. 闲聊兜底 + 未命中回落到通用 RAG 检索

## 与用户长期目标的关系

- 用户的方向（先做 RAG + 知识治理 + 评测，暂不训练模型）与本仓库现状**基本吻合**：仓库已经是 RAG 架构，已有意图路由、固定合规话术、检索回落。
- 主要缺口在用户最关心的两块：**会话持久化 + 评分/评测后台**。详见 `docs/04-known-problems.md` 与 `tasks/TASK-0001-repo-audit.md`。

## 由代码确认的关键事实（前端集成）

- 前端**只发 `{question}`，不发 `session_id`** → 后端每条消息新建 `api-<uuid>` 会话 → **当前跨消息无多轮记忆，也无稳定用户/角色标识**。
- 这直接影响「维护会话 + 评分」：目前没有「一次完整对话」的概念，也无法把评分归因到某个用户/角色/门店。
